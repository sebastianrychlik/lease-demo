# M1.0 — Angular Foundation

## Objective

Establish the enterprise Angular frontend architecture for the Lease Demo project.

This milestone creates only the project structure, infrastructure, and architecture skeleton.
No business functionality is implemented.

---

## Scope

- Angular 18 project scaffolded manually (no `ng new`)
- Standalone component architecture throughout
- Lazy-loading ready routing
- Core infrastructure layer (services, interceptors, guards)
- Shared UI layer (components, pipes, directives)
- Feature and layout folder placeholders
- Environment configuration for local and production
- TypeScript strict mode enabled

## Architecture Decisions

### Standalone Components

All components, pipes, and directives use `standalone: true`.
No NgModules are used. This is the Angular 17+ recommended approach.

### inject() Function

Constructor injection is replaced by the `inject()` function throughout.
This enables tree-shakable, testable, and composable dependency injection.

### OnPush Change Detection

All components use `ChangeDetectionStrategy.OnPush`.
This ensures change detection only triggers when inputs change or signals emit,
improving rendering performance.

### Signals

`AuthService` uses Angular signals (`signal<>`, `.asReadonly()`) for reactive state.
The architecture is signals-ready for future feature services.

### Functional Interceptors

HTTP interceptors use the functional `HttpInterceptorFn` pattern (Angular 15+).
Registered via `withInterceptors([...])` in `app.config.ts`.

### Lazy Loading

All routes use `loadComponent` or `loadChildren` for lazy loading.
Feature bundles are only loaded when the user navigates to that route.

### Path Aliases

TypeScript path aliases are configured in `tsconfig.json`:

```
@core/*   → src/app/core/*
@shared/* → src/app/shared/*
@features/* → src/app/features/*
@layouts/*  → src/app/layouts/*
@env/*      → src/environments/*
```

## Design Decisions

| Decision | Rationale |
|---|---|
| Standalone components | Angular 17+ standard; eliminates NgModules boilerplate |
| inject() | Cleaner than constructor injection; tree-shakable |
| OnPush everywhere | Better performance; forces explicit state management |
| Signals in AuthService | Future-ready reactive state without RxJS overhead |
| Functional interceptors | Angular 15+ standard; avoids class-based DI complexity |
| Lazy routes from day 1 | Prevents architectural debt; enforces bundle splitting |
| No mock data | Architecture milestone only; data comes in later milestones |
