# M2.0 — Exchange Rates

## Overview

Implements the first complete business feature: retrieving and displaying current exchange rates from the Polish National Bank (NBP) public API.

The feature is a full vertical slice from the Angular frontend through the Spring Boot backend to the external NBP API. No database, caching, authentication, or persistence is involved.

---

## Architecture

```
Angular Component (ExchangeRatesPageComponent)
        │
ExchangeRateService  [frontend/features/exchange-rates/services/]
        │
ApiService           [frontend/core/services/]
        │ HTTP GET /api/exchange-rates
Spring ExchangeRateController  [exchange/controller/]
        │
ExchangeRateService            [exchange/service/]
        │
NbpClient                      [exchange/client/]
        │ HTTP GET https://api.nbp.pl/api/exchangerates/tables/A?format=json
NBP Public API
```

## Backend

### Package Structure

```
com.luxsoft.dxc.exchange/
├── client/
│   └── NbpClient.java               # RestClient wrapper for NBP API
├── config/
│   └── NbpClientConfig.java         # RestClient Spring Bean configuration
├── controller/
│   └── ExchangeRateController.java  # GET /api/exchange-rates
├── dto/
│   ├── external/
│   │   ├── NbpTableDto.java         # External DTO — NBP table JSON
│   │   └── NbpRateDto.java          # External DTO — NBP rate entry JSON
│   └── response/
│       ├── ExchangeRateResponse.java # Internal DTO — our public API contract
│       └── ExchangeRateDto.java      # Internal DTO — single rate entry
├── exception/
│   └── NbpClientException.java      # Application exception for NBP failures
├── mapper/
│   └── ExchangeRateMapper.java      # MapStruct mapper: NBP DTOs → internal DTOs
└── service/
    └── ExchangeRateService.java     # Orchestrates client + mapper
```

### REST Contract

```
GET /api/exchange-rates
```

**Response — HTTP 200 OK**

```json
{
  "tableNo": "150/A/NBP/2025",
  "effectiveDate": "2025-08-01",
  "rates": [
    {
      "code": "USD",
      "name": "dolar amerykański",
      "midRate": 3.9245
    }
  ]
}
```

**Error — HTTP 502 Bad Gateway** (NBP API unavailable)

```json
{
  "type": "about:blank",
  "title": "NBP API Unavailable",
  "status": 502,
  "detail": "Failed to fetch exchange rates from NBP API."
}
```

### DTO Separation

Two distinct DTO layers prevent the external NBP contract from leaking into our public API:

| Layer | Classes | Purpose |
|---|---|---|
| External DTOs | `NbpTableDto`, `NbpRateDto` | Deserialise the raw NBP JSON response |
| Internal DTOs | `ExchangeRateResponse`, `ExchangeRateDto` | Define our own public API contract |

External DTOs are never serialised to HTTP responses. Internal DTOs are never used for NBP deserialisition.

### MapStruct Mapper

`ExchangeRateMapper` is a MapStruct `@Mapper(componentModel = "spring")` interface that converts:

- `NbpRateDto` → `ExchangeRateDto` (field renames: `currency` → `name`, `mid` → `midRate`)
- `NbpTableDto` → `ExchangeRateResponse` (field rename: `no` → `tableNo`)

The mapper contains no business logic — all conversions are declarative `@Mapping` annotations.

### RestClient Usage

`NbpClientConfig` registers a `RestClient` Spring bean pre-configured with the NBP base URL:

```java
RestClient.builder()
    .baseUrl("https://api.nbp.pl")
    .build();
```

`NbpClient` injects this bean by name (`nbpRestClient`) and calls:

```
GET https://api.nbp.pl/api/exchangerates/tables/A?format=json
```

`RestTemplate` is not used anywhere in this feature.

### Error Handling

`NbpClientException` (a `RuntimeException`) is thrown when:

- The NBP API is unreachable (`RestClientException`)
- The NBP API returns an empty response

`GlobalExceptionHandler` maps `NbpClientException` → HTTP 502 Bad Gateway via Spring's `ProblemDetail`. Low-level `RestClientException` is never exposed to the caller.

## Frontend

### Feature Structure

```
src/app/features/exchange-rates/
├── exchange-rates.routes.ts         # Lazy-loaded route definitions
├── models/
│   └── exchange-rate.model.ts       # ExchangeRate, ExchangeRateResponse interfaces
├── pages/
│   └── exchange-rates-page.component.ts  # Page component with table + state management
└── services/
    └── exchange-rate.service.ts     # Calls ApiService, exposes Observable
```

### Routing

Route registered in `app.routes.ts`:

```typescript
{
  path: 'exchange-rates',
  loadChildren: () =>
    import('./features/exchange-rates/exchange-rates.routes')
      .then(m => m.EXCHANGE_RATES_ROUTES),
}
```

The feature is lazily loaded. The dashboard remains available at `/dashboard`.

### Angular Service

`ExchangeRateService` delegates to the existing `ApiService`:

```typescript
getExchangeRates(): Observable<ExchangeRateResponse> {
  return this.api.get<ExchangeRateResponse>('/exchange-rates');
}
```

No HTTP code is duplicated — `ApiService` is reused as the single HTTP abstraction.

### Typed Models

All frontend models are strictly typed interfaces (`no any`, `no Record<string, any>`):

```typescript
export interface ExchangeRate {
  code: string;
  name: string;
  midRate: number;
}

export interface ExchangeRateResponse {
  tableNo: string;
  effectiveDate: string;
  rates: ExchangeRate[];
}
```

### Reactive State

`ExchangeRatesPageComponent` uses Angular Signals to manage a discriminated union state:

```typescript
type ExchangeRatesViewState =
  | { status: 'loading' }
  | { status: 'success'; data: ExchangeRateResponse }
  | { status: 'empty' }
  | { status: 'error'; message: string };

readonly viewState = signal<ExchangeRatesViewState>({ status: 'loading' });
```

All four states are explicitly rendered in the template:

| State | Displayed UI |
|---|---|
| `loading` | "Loading..." |
| `success` | Exchange rates table |
| `empty` | "No exchange rates available." |
| `error` | "Error downloading data" + message + Retry button |

The subscription is managed within the component's `load()` method. No unmanaged subscriptions.

### Component Display

The table displays per rate:

- Currency **code** (e.g. `USD`)
- Currency **name** (e.g. `dolar amerykański`)
- **Mid rate** (e.g. `3.9245`)

Metadata shown above the table: table number and effective date.

## Known Limitations

- No caching: every page load triggers a live NBP API call.
- No authentication on the backend endpoint.
- No pagination: the full NBP Table A list (~35 currencies) is loaded at once.
- The component subscribes imperatively; a future refactor could use `async` pipe with `toSignal`.
- No database persistence of historical rates.
